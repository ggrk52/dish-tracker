## 💡 О проекте

**Чистая Тарелка PRO** — это бескомпромиссный, быстрый и отзывчивый веб-трекер кухонных дежурств, созданный для того, чтобы навсегда закрыть вопрос: *«Чья сейчас очередь мыть посуду?»*.

Приложение объединяет эстетику операционных систем Apple (VisionOS floating island dock, OKLCH glassmorphism, мягкие градиентные ауры) с глубокой геймификацией: 3D-пьедесталом победителей, шкалой семейного вклада, системой наград, синтезированными звуками победы и интерактивными реакциями на каждую помывку.

Работает одинаково безупречно как **автономное локальное приложение** на микрокомпьютере (Raspberry Pi, домашний Linux-сервер, роутер), так и как **полноценное облачное PWA** в интернете с синхронизацией между смартфонами и планшетами всех членов семьи или команды.

## ✨ Ключевые возможности

- 🪟 **Дизайн Apple VisionOS & Glassmorphism**: Парящая нижняя панель навигации (Floating Dock), глубокие размытия фона (backdrop-blur), палитра современного цветового пространства OKLCH и живая неоновая подсветка активного дежурного.
- ⚡ **Zero Dependencies (0 внешних библиотек)**: Чистый Vanilla JavaScript (ES2023+) и семантический HTML5/CSS3. Никаких тяжелых фреймворков, бандлеров или npm-уязвимостей. Мгновенная загрузка за 0.05 сек.
- 🔄 **Micro-Diffing Engine**: Архитектура инкрементального обновления DOM по хэш-слепкам состояния. Никакого мерцания экранов, минимальная нагрузка на процессор и колоссальная экономия заряда аккумулятора смартфона.
- 🔊 **Встроенный Web Audio синтезатор**: Тактильные щелчки, всплывающий «поп» и победный аккорд (C5–E5–G5–C6), генерируемые процедурно на лету без загрузки внешних аудиофайлов.
- 📱 **PWA & Офлайн-режим**: Полноценный Service Worker кэширует всё приложение. Добавляется на экран «Домой» в iOS и Android как нативное приложение без адресной строки браузера.
- ☀️ **Screen Wake Lock**: Режим предотвращения засыпания экрана — идеально для настенного планшета или смарт-дисплея на кухне.
- 🔐 **Ролевая безопасность и PIN-защита**: Разделение прав доступа. Гости могут просматривать статистику, а отмечать смену, менять порядок и настраивать сервер могут только авторизованные дежурные или Администратор.
- ☁️ **Гибридная синхронизация**: Мгновенный обмен данными через локальный Wi-Fi (In-Memory HTTP с поддержкой ETag 304 Not Modified) либо через глобальные облачные провайдеры (Firebase Realtime DB, Cloudflare Workers KV).
- 📊 **Экспорт и отчетность**: Выгрузка всей истории моек в CSV/Excel за один клик и умная генерация форматированного сводного дайджеста для отправки в Telegram или WhatsApp.

## 🧩 Подробный обзор разделов

### 1. 🧼 Таб «Дежурство» (Duty Hero View)

Центральный хаб приложения, отвечающий за текущий статус на кухне:

- **Hero-карточка дежурного**: Динамическая карточка с мягким радиальным градиентом в цвет персонального профиля, анимированным кольцом активности и аватаром.
- **Динамический таймер**: Автоматически считает, сколько часов и минут длится текущая смена (`⏱️ Дежурит 2 ч. 30 мин.`).
- **Счётчик опыта**: Показывает суммарное число закрытых смен конкретного участника.
- **Главная кнопка «Я ПОМЫЛ ПОСУДУ!»**: Большой эргономичный элемент управления с эффектом стеклянного блика и тактильным откликом. Нажатие запускает салют из конфетти на весь экран, проигрывает победный марш и автоматически передает эстафету следующему дежурному.
- **Быстрые модификаторы смены**:
  - `🔄 Поменяться`: Позволяет передать смену другому участнику в один клик без сбивания общего цикла.
  - `⏩ Пропустить`: Экстренный пропуск очереди (например, если участник в поездке или болен).
  - `📝 С заметкой`: Возможность прикрепить комментарий к помывке с помощью быстрых тегов (*«Гора кастрюль и сковородок 🍳»*, *«Блестит до скрипа ✨»*, *«После праздничного обеда 🍰»*, *«Помыл без напоминаний! 🌟»*).
- **Интерактивный трек очереди**: Визуальная лента следующих участников со статусами (*«Сейчас 🧼»*, *«Следующий 🔔»*, *«Через 2 смены»*). Кнопка **«Изменить порядок»** открывает удобное модальное окно для перестановки участников стрелками вверх/вниз.
- **Блок последней активности**: Экспресс-сводка последней завершенной помывки прямо на главном экране.

### 2. 📜 Таб «История» (Timeline Journal)

Полноценная бортовая летопись кухонной чистоты:

- **Группировка по дням**: Помывки автоматически объединяются в хронологические блоки (*«Сегодня»*, *«Вчера»*, *«23 октября»* и т.д.).
- **Информативные карточки**: Точное время завершения, длительность нахождения на смене, имя, аватар и прикрепленная заметка дежурного.
- **Семейные реакции (❤️, 👏, 🌟)**: Интерактивная система похвалы. Любой член семьи или команды может поставить лайк, отправить аплодисменты или звезду за качественно вымытую сковороду. Реакции моментально синхронизируются между всеми экранами.
- **Быстрые фильтры**: Чипы вверху экрана позволяют в один клик отфильтровать журнал по конкретному человеку или показать общую ленту.
- **Экспорт в CSV**: Кнопка **«📥 Скачать»** генерирует структурированный файл `dish_duty_history.csv` с датами, именами, длительностью, заметками и лайками для анализа в Excel, Apple Numbers или Google Таблицах.

## 🚀 Локальное развертывание на сервере

Серверная часть спроектирована с упором на максимальную надежность, нулевое потребление ресурсов и долговечность флеш-памяти (MicroSD в Raspberry Pi).

### Особенности архитектуры `server.py`:
- **In-Memory кэширование**: Все запросы на чтение (`GET /api/state`) отдаются мгновенно из оперативной памяти без постоянного дергания диска.
- **Поддержка ETag и 304 Not Modified**: Если состояние кухни не изменилось, сервер возвращает пустой заголовок `304` за **< 1 мс**, передавая **0 байт** тела.
- **Сжатие Gzip на лету**: Все статические ассеты и JSON отдаются в сжатом виде, экономя мобильный трафик.
- **Атомарная запись**: Сохранение в `data.json` происходит безопасно через временный файл с блокировкой потоков (`threading.Lock`), исключая повреждение базы при внезапном отключении электричества.
- **Стандартная библиотека**: Работает на любом Python 3.8+ без необходимости выполнения `pip install`.

### Вариант 1: Запуск на Raspberry Pi / Linux (Systemd-сервис)

Это рекомендуемый способ для домашнего мини-сервера (работает 24/7, стартует автоматически при включении питания).

#### 1. Клонирование репозитория
```bash
cd ~
git clone https://github.com/ваш-логин/dish-tracker.git
cd dish-tracker
```

#### 2. Проверка запуска вручную
```bash
python3 server.py
# Сервер запустится на http://0.0.0.0:8080
```

#### 3. Настройка автозапуска через Systemd
Создайте файл службы:
```bash
sudo nano /etc/systemd/system/dish-tracker.service
```

Вставьте следующую конфигурацию (замените `pi` на имя вашей учетной записи Linux, если оно отличается, например `ubuntu`):

```ini
[Unit]
Description=Dish Tracker PRO - Умный трекер и график дежурств
After=network.target

[Service]
Type=simple
# Имя пользователя в Linux (например, pi или ubuntu):
User=pi
WorkingDirectory=/home/pi/dish-tracker
ExecStart=/usr/bin/python3 /home/pi/dish-tracker/server.py
Restart=always
RestartSec=3
Environment=PORT=8080

[Install]
WantedBy=multi-user.target
```

Активируйте и запустите службу:
```bash
# Перезагружаем конфигурацию systemd
sudo systemctl daemon-reload

# Включаем автоматический запуск при старте системы
sudo systemctl enable dish-tracker

# Запускаем сервис прямо сейчас
sudo systemctl start dish-tracker

# Проверяем статус работы
sudo systemctl status dish-tracker
```

#### Полезные команды управления:
```bash
# Посмотреть живые логи сервера
journalctl -u dish-tracker -f

# Перезапустить службу
sudo systemctl restart dish-tracker

# Остановить службу
sudo systemctl stop dish-tracker
```

### 🌟 Вариант А: Firebase Realtime Database (Самый простой, 100% бесплатно)

Идеальный вариант: не требует белого IP, роутеров, открытых портов или постоянно включенного компьютера.

1. Перейдите в [Google Firebase Console](https://console.firebase.google.com/) и войдите под вашим Google-аккаунтом.
2. Нажмите **«Создать проект»** (назовите его, например, `dish-tracker`).
3. В левом меню раскройте раздел **«Сборка» (Build)** ➔ **«Realtime Database»** и нажмите **«Создать базу данных»**.
4. Выберите ближайший регион (например, *Belgium / europe-west1*).
5. Перейдите во вкладку **«Правила» (Rules)** и вставьте:
   ```json
   {
     "rules": {
       ".read": true,
       ".write": true
     }
   }
   ```
   Нажмите **«Опубликовать» (Publish)**.
6. В верхней части вкладки «Данные» скопируйте полученный URL базы:
   ```text
   https://ваш-проект-default-rtdb.europe-west1.firebasedatabase.app/
   ```
7. Откройте приложение **Чистая Тарелка**, перейдите в **«Настройки» (☰)**, вставьте скопированный URL в поле **«Облачная синхронизация»** и нажмите **«Сохранить»**.

*Готово! Теперь статус в шапке изменится на «В облаке 🟢», а все телефоны участников будут синхронизироваться моментально через Google Cloud.*

### ⚡ Вариант Б: Cloudflare Workers + KV (Быстро и без блокировок)

Отличное решение для пользователей в регионах, где сервисы Google могут работать нестабильно. Cloudflare предоставляет 100 000 бесплатных запросов ежедневно.

Файлы бэкенда уже входят в состав репозитория:
- `cloudflare-worker.js` / `worker.js`
- `wrangler.toml`

#### Развертывание через Cloudflare Dashboard (в браузере):
1. Зарегистрируйтесь бесплатно на [cloudflare.com](https://cloudflare.com).
2. В боковом меню перейдите в **«Workers & Pages»** ➔ **«Create application»** ➔ **«Create Worker»**.
3. Назовите воркер (например, `dish-sync`) и нажмите **«Deploy»**.
4. Нажмите **«Edit code»**, удалите стандартный шаблон, вставьте содержимое файла [`cloudflare-worker.js`](cloudflare-worker.js) из этого репозитория и нажмите **«Deploy»**.
5. Вернитесь в настройки воркера ➔ вкладка **«Settings»** ➔ **«Variables»** ➔ раздел **«KV Namespace Bindings»**.
6. Создайте KV-хранилище с именем `DISH_KV` и привяжите его к переменной `DISH_KV`.
7. Скопируйте адрес воркера (вида `https://dish-sync.ваш-аккаунт.workers.dev`) и укажите его в поле облачной синхронизации в настройках трекера.

### 🛡️ Вариант В: Удаленный доступ к вашему серверу через Cloudflare Tunnel

Если ваш трекер запущен дома на Raspberry Pi, но вы хотите открывать его из любой точки мира по собственному красивому домену с бесплатным HTTPS:

1. Установите агент на Raspberry Pi:
   ```bash
   curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb
   sudo dpkg -i cloudflared.deb
   ```
2. Авторизуйтесь в Cloudflare:
   ```bash
   cloudflared tunnel login
   ```
3. Создайте постоянный туннель к локальному порту 8080:
   ```bash
   cloudflared tunnel create dish-tunnel
   cloudflared tunnel route dns dish-tunnel dishes.yourdomain.com
   cloudflared tunnel run --url http://localhost:8080 dish-tunnel
   ```
4. Теперь сервер доступен по адресу `https://dishes.yourdomain.com` без открытых портов на роутере и без белого IP!

### 🔒 Вариант Д: Приватный VPN-доступ через Tailscale (WireGuard Mesh)

Наиболее защищенный способ для дома и семьи: не требует покупки собственного домена, белого IP или проброса портов (Port Forwarding) на роутере. Все ваши устройства связываются в единую зашифрованную Mesh-сеть по протоколу WireGuard.

#### 1. Установка Tailscale на сервер (Raspberry Pi / Linux):
```bash
# Установка официальным скриптом
curl -fsSL https://tailscale.com/install.sh | sh

# Авторизация и запуск (перейдите по выданной ссылке для входа)
sudo tailscale up
```

#### 2. Подключение смартфонов:
1. Установите приложение **Tailscale** на телефоны всех участников ([iOS App Store](https://apps.apple.com/app/tailscale/id1470499037) / [Google Play](https://play.google.com/store/apps/details?id=com.tailscale.ipn)).
2. Авторизуйтесь под той же учетной записью (Google / Apple / Microsoft / GitHub).

#### 3. Вход в трекер:
- Если в панели управления Tailscale включен **MagicDNS**, трекер доступен с любого подключенного смартфона по короткому имени вашего сервера:
  ```text
  http://dish-pi:8080
  ```
- Либо по персональному IP-адресу сервера в сети 100.x.y.z:
  ```text
  http://100.x.y.z:8080
  ```

*Плюсы: нулевая видимость для внешних сканеров интернета, сквозное шифрование и мгновенный отклик.*

### ⚡ Вариант Е: Экспресс-доступ через Ngrok (запуск за 30 секунд)

Самый быстрый способ моментально поделиться ссылкой с HTTPS или протестировать синхронизацию на мобильном интернете без регистрации доменов.

#### 1. Установка Ngrok:
- **Linux / Raspberry Pi**:
  ```bash
  curl -s https://ngrok-agent.s3.amazonaws.com/ngrok.asc | sudo tee /etc/apt/trusted.gpg.d/ngrok.asc >/dev/null
  echo "deb https://ngrok-agent.s3.amazonaws.com buster main" | sudo tee /etc/apt/sources.list.d/ngrok.list
  sudo apt update && sudo apt install ngrok
  ```
- **macOS**:
  ```bash
  brew install ngrok/ngrok/ngrok
  ```

#### 2. Авторизация токена:
Зарегистрируйтесь на [ngrok.com](https://ngrok.com) и привяжите токен:
```bash
ngrok config add-authtoken ВАШ_AUTHTOKEN
```

#### 3. Проброс сервера в интернет:
```bash
# Запуск туннеля к локальному порту 8080:
ngrok http 8080
```
*(Если вы закрепили бесплатный статический домен в личном кабинете Ngrok:)*
```bash
ngrok http 8080 --domain=your-subdomain.ngrok-free.app
```

Ngrok выдаст постоянный защищенный адрес вида `https://xxxx.ngrok-free.app`. Просто откройте его на телефоне и добавьте на главный экран как PWA!

## 🔌 Справочник REST API сервера

Локальный сервер предоставляет лаконичный и быстрый REST API:

| Метод | Эндпоинт | Описание | Особенности |
|:---:|:---|:---|:---|
| `GET` | `/api/state` | Получение текущего состояния приложения | Поддерживает заголовок `If-None-Match` и возвращает `304 Not Modified` при отсутствии изменений |
| `POST` | `/api/state` | Сохранение обновленного состояния (мойка, смена) | Требует заголовки авторизации `X-Auth-User` и `X-Auth-Token` |
| `POST` | `/api/login` | Проверка учетных данных пользователя | Возвращает сессионный токен на основе SHA-256 |
| `GET` | `/api/backup` | Полная выгрузка базы данных в JSON | Доступно Администратору |
| `POST` | `/api/backup` | Восстановление базы данных из JSON-архива | Доступно Администратору |
